# Постоянный локальный запуск

Этот сценарий сохраняет накопленные события между запусками. Выполняйте команды из корня проекта и используйте тот же каталог и Compose-проект при следующем запуске.

## Запуск

Если уже используются review-контейнеры на PostgreSQL `15432` и Elasticsearch `19200`, достаточно выбрать `Event Mosaic Local` в IDEA и нажать Run. Карта открывается на <http://127.0.0.1:18080>; frontend собирается автоматически без Vite и ручного PATH на подготовленном Windows-проекте. Stop/Run сохраняет данные этого же стека. Подробности находятся в [README](../../README.md#обычный-запуск-из-intellij-idea). Команды ниже относятся к отдельному Compose-стеку на стандартных портах; не переключайтесь между ними в ожидании общей базы.

Поднимите PostgreSQL и Elasticsearch:

```shell
docker compose -f compose.local.yml up -d
```

Запустите Spring на Windows:

```powershell
.\gradlew.bat bootRun
```

На macOS:

```shell
sh ./gradlew bootRun
```

Откройте [карту Spring Boot](http://127.0.0.1:8080/): Gradle включает frontend в ресурсы приложения. Для запуска готового JAR без Gradle, Node.js/npm и Vite используйте [команды сборки и запуска](../../README.md#собранное-приложение-без-vite). При запуске JAR подключения к PostgreSQL и Elasticsearch задаются явно; автоматическое управление Compose остается только в режиме разработки.

Для разработки интерфейса можно дополнительно запустить Vite. На Windows выполните `.\run-frontend.cmd`, на macOS перейдите в `frontend`, выполните `npm ci`, затем `npm run dev -- --host 127.0.0.1 --open`. Vite обращается к Spring на порту `8080`. Перед `clean build` остановите Vite, чтобы он не удерживал устанавливаемые файлы на Windows.

Автоматическая загрузка включена по умолчанию (`event-mosaic.ingestion.gdelt.automatic.enabled=true`). После готовности Spring первый цикл получает свежую пару Event/Mention, затем восстанавливает текущее суточное окно. Следующий опрос начинается через минуту после завершения предыдущего цикла. Один цикл ограничен 12 минутами, право на его выполнение действует 15 минут и не продлевается фоновым heartbeat. Если весь объем не обработан, следующий цикл продолжает сохраненный план.

На пустой установке API временно недоступен до появления поискового индекса, затем честно показывает частичное покрытие до обработки всех 96 интервалов событий. Frontend обновляет данные каждые 15 минут. Чтобы открытый экран сразу получил уже готовые данные, его можно обновить вручную.

Для запуска только с сохраненными данными передайте `--event-mosaic.ingestion.gdelt.automatic.enabled=false` после имени JAR, через `bootRun --args` или настройку запуска IDE. Это также способ остановить автоматическую загрузку при диагностике: схема базы и накопленные данные сохраняются.

Для явного одиночного цикла на Windows:

```powershell
.\gradlew.bat bootRun --args="--event-mosaic.ingestion.gdelt.one-shot-enabled=true"
```

На macOS замените начало команды на `sh ./gradlew bootRun` с тем же аргументом. Явный одиночный режим выполняет один ограниченный цикл при старте; web-процесс остается доступен и останавливается обычным способом. Он использует общий журнал состояния и не запускает автоматический scheduler.

## Остановка и продолжение

1. Остановите Spring через `Ctrl+C` или кнопку остановки в IDE; если использовали отдельный Vite, остановите и его.
2. Остановите инфраструктуру:

   ```shell
   docker compose -f compose.local.yml stop
   ```

3. При следующем запуске повторите `docker compose -f compose.local.yml up -d`, затем запустите тот же JAR или `bootRun`. Vite нужен только для отдельного режима разработки интерфейса.

PostgreSQL и Elasticsearch хранят данные в именованных volumes `postgres-data` и `elasticsearch-data`. ZIP и CSV сохраняются в `.local/gdelt` (либо в явно заданном `staging-root`). Сохраняйте этот каталог: проверенный ZIP нужен для восстановления. Остановка и запуск не удаляют историю, не пересоздают базу и не сбрасывают состояние попыток. После принудительной остановки незавершенная работа становится доступна по истечении сохраненного срока владения. Если прервалась последняя разрешенная попытка серии, новая серия ждет дополнительную паузу `maximum-delay`, отсчитываемую от окончания срока владения.

## Повторы и состояние

При явно включенном автоматическом режиме первый цикл начинается после готовности Spring, последующие - через минуту после завершения предыдущего. Один worker сначала обрабатывает новую пару Event/Mention, затем заполняет зарегистрированные пропуски суточного окна. За цикл выбирается не больше `due-work-limit` готовых локальных архивов (по умолчанию `256`). Неизменившийся список GDELT сам по себе не вызывает повторную загрузку или полный просмотр индекса.

Временная ошибка источника не отменяет готовую локальную работу. После трех автоматических повторов сохраняется пауза ровно `maximum-delay` (по умолчанию 15 минут), затем начинается новая серия. Счетчик всех попыток и последняя причина исчерпания сохраняются. Неповторяемые ошибки и архивы, вышедшие из текущего плана, автоматически не получают новую серию. Некорректный временный список GDELT повторяется без регистрации непроверенных данных.

Подтвержденные архивы проверяются отдельно: по умолчанию не чаще одного пакета в 15 минут, максимум два самых давно проверенных архива. Недостающие документы открывают повтор обработки, лишние документы или потерянный физический индекс требуют существующего [восстановления раздела](partition-rebuild.md). Сбой диагностического запроса не отменяет ранее подтвержденную индексацию.

`/actuator/health/pipeline` показывает состояние цикла, возраст успешного запроса к источнику, отставание данных, паузы и количество оставшихся Event/Mention. Остановка scheduler и недоступность GDELT диагностируются отдельно. Эти состояния не меняют `/actuator/health/liveness` и `/actuator/health/readiness`; готовность зависит от локальной инфраструктуры. Недостаток места останавливает новые операции, увеличивающие объем данных.

## Явное удаление

`docker compose -f compose.local.yml down -v` удаляет volumes PostgreSQL и Elasticsearch и теряет их данные. Это сброс, а не обычная остановка. `.local/gdelt` находится отдельно от volumes и этой командой не удаляется.

`tools/map-review/stop-map-review.ps1` также удаляет данные, но только отдельного одноразового проверочного стека. Его порты и volumes отличаются от постоянного локального запуска. Автоматическое удаление старых событий, ZIP/CSV или версий индекса не выполняется; срок хранения и резервное копирование требуют отдельного решения.
